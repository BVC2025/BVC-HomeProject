# HRMS AI Assistant — module guide

Self-contained Gemini-powered RAG assistant grounded on
`docs/HRMS_KNOWLEDGE.md`.

## What it is

- Read-only chat that answers employee questions using **only** the
  HRMS knowledge document.
- Detects the user's language and replies in the same one.
- Runs a second Gemini call as a **grounding check** — if the answer
  isn't supported by the retrieved chunks, the endpoint returns a
  canned "I don't have that information" reply instead.
- Persists conversation history per `SESSION_ID` in its own table
  (`hrms_ai_conversation`) — never touches any HRMS data.

## Files

```
backend/app/hrms_ai/
├── __init__.py
├── schemas.py                pydantic request/response models
├── session_store.py          SQLAlchemy model — hrms_ai_conversation
├── gemini_client.py          thin google-generativeai wrapper
├── knowledge_builder.py      chunk + embed HRMS_KNOWLEDGE.md → JSON index
├── rag.py                    cosine retrieval over the index
├── prompt.py                 system instruction + grounding prompt
├── routes.py                 FastAPI endpoints (/hrms-ai/*)
├── build_docx.py             optional: .md → .docx for HR handoff
├── knowledge_index.json      generated by knowledge_builder.py
└── README.md                 this file

docs/HRMS_KNOWLEDGE.md        the ONLY factual source
```

## Endpoints

- `GET  /hrms-ai/status`             — feature flag + config check (no auth)
- `POST /hrms-ai/ask`                — ask a question
- `GET  /hrms-ai/history/{sid}`      — a session's chat history
- `DELETE /hrms-ai/history/{sid}`    — clear a session
- `POST /hrms-ai/rebuild`            — admin: regenerate embeddings

## Environment variables

Add to `backend/.env`:

```
GEMINI_API_KEY=<your key from https://aistudio.google.com/apikey>
GEMINI_MODEL=gemini-2.0-flash
GEMINI_EMBED_MODEL=text-embedding-004
HRMS_AI_ENABLED=true
```

`HRMS_AI_ENABLED=false` is the emergency kill switch — all endpoints
return 503 without touching Gemini or the DB.

## Install

```bash
pip install google-generativeai python-docx
```

Both are in `requirements.txt`.

## First-run steps

1. Ensure `docs/HRMS_KNOWLEDGE.md` exists (edit it as needed).
2. Build the embedding index:
   ```
   cd backend
   python -m app.hrms_ai.knowledge_builder
   ```
   Creates `backend/app/hrms_ai/knowledge_index.json`.
3. Start the server as usual. The assistant reads the index on first
   request and caches it in memory.
4. Optional: hand off a Word copy to HR:
   ```
   python -m app.hrms_ai.build_docx
   ```

## Rebuilding after doc edits

Every time you edit `docs/HRMS_KNOWLEDGE.md`, rebuild the index so the
new content is retrievable. Two ways:

- CLI:  `python -m app.hrms_ai.knowledge_builder`
- HTTP: `POST /hrms-ai/rebuild` (admin only) — no server restart needed;
        the in-memory RAG cache reloads automatically.

## Isolation guarantees

- The router prefix `/hrms-ai/*` never collides with any HRMS route.
- No `db.add()` / `db.commit()` inside this module touches any HRMS
  table. The only mutations happen on `hrms_ai_conversation`.
- The system prompt hard-blocks HR actions ("You are not an approver").
- The kill switch `HRMS_AI_ENABLED=false` disables every endpoint in
  one line if the assistant misbehaves.
